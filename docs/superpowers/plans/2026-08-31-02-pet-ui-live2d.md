# CodexPet Desktop UI and Live2D Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the static status page with the approved transparent desktop pet, interactions, menus, settings, fallback art, and a two-outfit Live2D model.

**Architecture:** The Rust core from Plan 01 remains the only task-state owner. A framework-free TypeScript UI consumes immutable snapshots, renders status chrome and interactions, and drives a renderer interface with interchangeable static-image and Cubism implementations.

**Tech Stack:** Tauri 2, vanilla TypeScript, Vitest + jsdom, CSS, Live2D Cubism SDK for Web, Cubism Editor

**Spec:** `docs/superpowers/specs/2026-08-31-codex-desktop-pet-design.md`

## Global Constraints

- Complete `2026-08-31-01-status-bridge-core.md` first.
- Windows 10/11 and WebView2 only.
- Keep one character model with default and maid outfit layers; do not create a second model.
- Preserve the approved round head, current squat body ratio, warm peach skin, and detailed hair/outfit shading.
- The pet must remain usable through the static PNG renderer when Live2D fails.
- Waiting confirmation may interrupt any interaction animation.
- Pet action cooldown is 1 second; interaction voice cooldown is 10 seconds.
- Manual expression persists until the user selects automatic expression again.
- Do not add a full UI framework, animation framework, or state library.
