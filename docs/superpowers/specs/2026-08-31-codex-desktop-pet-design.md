# CodexPet Windows 桌面宠物设计说明

- 日期：2026-08-31
- 状态：设计章节已确认，等待最终文档审核
- 平台：Windows 10/11

## 1. 项目目标

CodexPet 是一个完全独立运行的 Windows 桌面宠物。它监听已经存在的 Codex Desktop、Codex CLI 和 IDE 中的 Codex 任务，不负责创建、代理或执行任务。

第一版需要做到：

1. 根据 Codex 的待机、运行、等待确认、完成和失败/取消状态切换角色动作与表情。
2. 任务完成或等待确认时使用本地 GPT-SoVITS v2Pro 角色声音播报。
3. 提供多种随机待机动作，避免角色长时间重复同一表现。
4. 显示任务运行时间，并在多任务时显示数量和最高优先级状态。
5. 支持鼠标抚摸、戳动、拖动，以及通过右键菜单切换服装、表情和语音状态。
6. 在状态变化和互动时，从内置角色台词池中随机选择合适内容。

## 2. 第一版不做的内容

- 不支持 macOS 或 Linux。
- 不在桌宠内实现 Codex 对话或任务执行界面。
- 不读取或解析 Codex transcript 文件；该格式不是稳定接口。
- 不训练新的 TTS 模型，直接接入用户已有的 GPT-SoVITS v2Pro 模型。
- 不制作多个角色；只制作一个角色和两套服装。
- 不保存 Codex 对话、提示词、命令正文或完整任务历史。

## 4. 总体架构

```text
Codex Desktop / CLI / IDE
        │
        │ 用户级 Hooks + notify
        ▼
轻量事件转发器
        │ Windows 本地命名管道
        ▼
Tauri 2 / Rust 桌宠核心
        ├── 任务状态聚合与计时
        ├── 提醒、去重和本地设置
        ├── 托盘、开机启动和进程管理
        ├── WebView / TypeScript / Live2D
        └── GPT-SoVITS 本地服务
```

所有通信限定在本机当前用户范围内，不开放局域网端口。角色窗口使用 Tauri 2 的透明、无边框、置顶窗口；Live2D 使用 Cubism SDK for Web 在 WebView2 中渲染。

## 5. 组件边界

### 5.1 Codex 事件转发器

职责：

- 通过用户级 Codex Hooks 接收 `SessionStart`、`UserPromptSubmit`、`PermissionRequest`、`Stop` 等事件。
- 通过 Codex `notify` 接收 `agent-turn-complete`，补充完成通知。
- 将不同来源的负载转换成统一的最小事件，再发送给桌宠。
- 不读取 transcript，不转发提示词、命令正文或助手输出。

首次运行时由设置页提供“安装 Codex 连接”操作。安装前显示将要修改的配置，确认后才写入，并保留配置备份。卸载桌宠连接时只移除 CodexPet 自己添加的部分。

### 5.2 Rust 桌宠核心

职责：

- 监听当前用户专用的 Windows 命名管道。
- 校验、去重并按会话维护任务状态。
- 计算状态优先级、任务数量和运行时间。
- 调度提醒、语音队列和 GPT-SoVITS 进程。
- 保存设置和必要的运行快照。
- 提供托盘菜单、开机启动、显示/隐藏和退出功能。

Rust 核心是唯一的状态真源。界面关闭或重建时从核心重新获取快照，不能在界面层另存一套任务状态。

### 5.3 Live2D 显示层

职责：

- 根据核心快照播放动作、表情和服装图层。
- 显示状态气泡、任务计时和任务数量角标。
- 处理拖动、右键、抚摸和戳动。
- Live2D 加载失败时显示静态角色图，不影响提醒功能。

### 5.4 语音管理器

职责：

- 按需启动和停止 GPT-SoVITS `api_v2.py`。
- 维护高低优先级语音队列。
- 缓存已经生成的固定台词音频。
- 执行事件去重、台词冷却、完成合并和重要提醒打断。
- TTS 不可用时立即显示文字气泡并记录非阻塞错误。

### 5.5 本地存储

保存：

- 用户设置和窗口位置。
- 角色台词与分类。
- 活跃任务的开始时间和最近状态。
- 事件去重标识。
- 已生成的语音缓存。

不保存：

- Codex 对话内容。
- 用户提示词和命令正文。
- 助手完整输出。
- 完整任务历史。

## 6. 统一事件和任务状态

转发器只发送以下最小信息：

```text
event_id       事件去重标识
session_id     Codex 会话标识
turn_id        可用时提供的回合标识
event_type     session_started | running | permission_required |
               completed | failed | cancelled
occurred_at    事件时间
display_label  工作目录名称或 Codex 来源等非对话短标签；没有时使用“Codex 任务”
```

第一阶段需要用当前 Codex 版本的真实 Hook 样本验证字段映射。无法可靠判断失败或取消时，保留原状态并显示连接提示，不能猜测任务结果。

每个会话独立保存：

- 当前状态。
- 开始时间。
- 最近事件时间。
- 是否已经播报等待提醒和结果。
- 完成或失败后的展示截止时间。

## 7. 状态优先级和表现

多任务时，角色显示最高优先级状态：

```text
等待确认 > 失败/取消 > 已完成 > 运行中 > 待机
```

角标显示与当前状态相关的任务数量；右键任务详情显示所有活跃任务及各自计时。

| 状态 | 角色表现 | 语音规则 | 持续时间 |
| --- | --- | --- | --- |
| 待机 | 呼吸、眨眼，随机看向四周、伸懒腰或犯困 | 不为每次待机动作播报；只在少量进入待机或互动场景说话 | 每 20–45 秒随机小动作 |
| 运行中 | 专注工作动作，显示计时 | 进入状态最多播报一次 | 持续到下一状态 |
| 等待确认 | 举手、靠近或明显提醒动作 | 立即提醒一次；两分钟后仍未处理再提醒一次，默认不继续循环 | 持续到用户处理 |
| 已完成 | 庆祝动作和完成语音 | 十秒内多个完成事件合并播报 | 展示 10 秒 |
| 失败/取消 | 沮丧或安慰动作和一条语音 | 同一事件只播报一次 | 展示 10 秒 |

完成或失败展示结束后，回到当时仍存在的最高优先级状态。

## 8. 语音去重和调度

1. 使用 `{session_id}:{turn_id}:{event_type}` 作为首选去重键；缺少 `turn_id` 时使用规范化事件 ID。
2. Hooks 和 `notify` 重复报告同一结果时只播报一次。
3. 同一句角色台词五分钟内不重复。
4. 十秒内出现多个完成事件时合并为一条数量播报，例如“有三个任务完成了”。
5. 等待确认提醒可以中断待机或互动语音。
6. 过时的低优先级语音直接丢弃，队列不积压长串台词。
7. 文字气泡先于语音显示；冷启动语音较慢时，视觉提醒不会等待模型。
8. 勿扰模式关闭所有语音，但保留气泡、动作和等待确认提示。

## 9. 角色互动与 Live2D 动作

### 9.1 互动

- 抚摸：开心、眯眼、轻蹭鼠标，并从亲近台词池随机选择一句。
- 戳动：后仰、惊讶或轻微生气，并从反应台词池随机选择一句。
- 连续互动的动作冷却为 1 秒，互动语音冷却为 10 秒，防止反复触发。
- 互动状态只是临时覆盖；任务状态仍在后台继续，等待确认可以立刻打断互动。

### 9.2 Live2D 母图和分层

先按确认的概念方向重绘高分辨率透明母图，再进行分层。最低分层包括：

- 后发、侧发、前发和可独立摆动的发束。
- 脸部轮廓、耳朵和颈部。
- 左右眼白、虹膜、瞳孔、高光、上下眼睑和眉毛。
- 可变形嘴部和必要的口腔层。
- 身体、左右手臂和手部。
- 默认服装的独立部件。
- 女仆服装的独立部件。
- 必须随部件变形的高光和阴影层。

所有部件使用透明背景，不保留烘焙背景。两套服装共用头部、表情、身体参数和动作，仅通过图层显隐切换。

第一版参数覆盖：头部 X/Y/Z、身体摆动、呼吸、眨眼、视线、嘴型、头发物理、基础手臂动作和互动反应。动作至少覆盖五种任务状态、三种待机动作、抚摸、戳动、庆祝和失败反应。

## 10. 界面设计

### 10.1 角色右键菜单

高频操作：

- 当前状态、当前任务简要信息和计时。
- 任务详情。
- 默认服装/女仆服装切换。
- 自动或手动表情切换。
- 语音开关。
- 勿扰模式。
- 打开 Codex。
- 打开设置、隐藏桌宠和退出。

表情默认自动跟随任务状态。手动选择后保持到用户重新选择“自动”。

### 10.2 设置窗口

设置页分为：

- 常规：开机启动、始终置顶、任务计时和角色大小。
- 提醒：等待提醒延迟、补提醒次数、完成/失败播报开关。
- 语音：GPT-SoVITS 路径、参考音频配置、音量、测试、预热和停止。
- 角色：皮肤、默认表情、互动台词和气泡显示。
- Codex 连接：Hooks/notify 安装状态、重新安装、诊断和卸载。

### 10.3 任务详情

任务详情显示活跃和刚结束的任务，包括短标签、当前状态和用时。它不是任务历史页面，不显示对话内容。

## 11. 故障降级

- Codex 连接中断：显示灰色连接异常标记；现有任务进入“等待状态更新”，不误报完成或失败。
- 桌宠重启：恢复任务开始时间和最近状态，收到下一条事件后校正。
- GPT-SoVITS 启动或推理失败：立即显示文字气泡；状态、计时和 Live2D 继续工作；下一次需要语音时再重试。
- Live2D 资源损坏或 WebView 渲染失败：回退静态角色图片，保留气泡、菜单和提醒。
- 事件重复或乱序：去重后按允许的状态转换处理；过期事件不能覆盖更新状态。
- 配置安装失败：不留下半写入配置；从备份恢复并在连接页提供可理解的错误说明。

“连接异常”和“等待状态更新”是连接健康提示，不增加新的角色任务状态，角色仍只使用五种已确认状态。

## 12. 测试与验收

### 12.1 自动测试

- 状态转换：五种状态及允许的转移。
- 多任务聚合：优先级、数量、完成展示和回退。
- 计时：开始、恢复、完成和重启后的连续性。
- 提醒：立即提醒、两分钟补提醒和不无限循环。
- 去重：Hooks/notify 重复、乱序事件和五分钟台词冷却。
- 完成合并：十秒窗口内的数量播报。
- TTS 降级：启动失败、请求失败和服务退出。
- 存储：设置、快照和缓存清理。

### 12.2 集成测试

使用本地模拟转发器向命名管道发送单任务、多任务、重复、乱序和断线事件，验证核心快照、界面状态和语音队列。测试不能依赖真实 Codex 任务或真实 TTS 推理。

### 12.3 Windows 人工验证

- 透明背景、无边框、置顶和多显示器缩放。
- 拖动、右键菜单、任务详情、托盘和开机启动。
- 抚摸、戳动、表情与两套服装切换。
- Codex Desktop、CLI 和 IDE 来源的真实状态事件。
- GPT-SoVITS v2Pro 在 RTX 5060 8GB 上的冷启动、热启动和显存释放。
- Live2D 和 TTS 分别故障时的静态图与气泡降级。

### 12.4 验收指标

- 收到本地状态事件后，角色状态和文字提示在一秒内更新。
- 同一任务事件不会重复播报。
- 两个以上并发任务的优先级和各自计时正确。
- 任一可选组件故障都不会导致桌宠退出。
- TTS 未启动时，桌宠本体不占用模型显存。
- 桌宠本体的资源占用单独测量，不把 GPT-SoVITS 服务算入轻量指标。

## 13. 分阶段交付

### 阶段一：状态链路验证

验证当前 Codex 版本的 Hooks 与 `notify` 实际负载，完成最小事件转发器、命名管道和状态聚合测试。界面先使用简单静态占位角色。

### 阶段二：Windows 桌宠外壳

完成透明置顶窗口、托盘、设置、右键菜单、计时、气泡、鼠标互动和静态降级图。

### 阶段三：Live2D 素材与接入

完成高分辨率母图、两套服装分层、Cubism 建模、动作参数和状态映射，并接入桌宠显示层。

### 阶段四：角色语音

接入 GPT-SoVITS v2Pro，完成按需启动、缓存、去重、合并、冷却、勿扰和故障降级。

### 阶段五：联调与打包

完成真实 Codex 来源验证、Windows 人工测试、资源占用测量和安装包。

每个阶段必须单独通过验收后再进入下一阶段，避免 Live2D、TTS 和 Codex 状态链路同时出现问题时难以定位。
